Help — Multi-user, storage & conflict resolution


Simultaneous login: Yes. Each person opens the same GitHub Pages URL (or local copy), signs in with their account, Pulls shared data, works, then Pushes.


Where data lives: Canonical shared copy = JSON file in your private GitHub repo. Local IndexedDB is a per-browser cache for speed and offline use.


Not real-time (GitHub mode): Two people editing the same employee at once can overwrite each other (last Push wins). Prefer one editor per staff record. Always Pull before major edits and Push when finished.


Workflow: Pull → edit → Save → Push. Top bar has quick Pull/Push buttons.







1. IndexedDB conflict resolution strategies


IndexedDB is local to each browser profile. Conflicts appear when (a) multiple tabs on the same machine write the cache, or (b) local cache diverges from the GitHub shared file after offline edits.




StrategyHow it worksIn this app




Last-write-wins (LWW)
Newest timestamp or version replaces older data. Simple; may drop concurrent edits.
GitHub Push uses file SHA; if remote changed, push fails until you Pull (see optimistic locking below).




Optimistic concurrency (SHA / version)
Read current version (SHA). Write only if SHA still matches. On mismatch → conflict → reload and retry.
Implemented for GitHub: githubPush() re-fetches SHA; HTTP 409 / SHA mismatch → “Pull, then Push again”.




Pull-before-edit
Always refresh shared state before opening a record for editing.
Recommended workflow. Auto-Pull runs after login when GitHub is configured.




Record-level locking (soft)
Mark a record as “being edited by X until T”. Others see a warning.
Not built-in (would need real-time presence). Coordinate by section or staff name.




Merge by field / CRDT
Merge non-overlapping field changes; use CRDTs for automatic merge.
Not implemented (complex). Manual merge: Pull, re-apply your field changes, Push.




Tab-level coordination
BroadcastChannel or storage events notify other tabs on the same origin.
Local cache is single-writer per save; avoid editing the same log in two tabs.




Snapshot + audit
Keep previous versions (Git history on GitHub provides this).
Each Push is a Git commit — use GitHub history to recover an overwritten version.

2. Firebase Realtime Database — investigation


Firebase Realtime Database (RTDB) is a cloud-hosted JSON tree with live listeners. It is a strong option when true simultaneous multi-user editing is required beyond GitHub file sync.




TopicFinding



What it isNoSQL JSON tree; clients subscribe with on("value") / on("child_changed") and receive updates in milliseconds.


Multi-userDesigned for concurrent clients. Security Rules control read/write per path (e.g. per lab, per role).


Conflict handlingLast write to a path wins at the leaf; use transactions (transaction()) for counters or conditional updates; structure data so different users write different paths when possible.


OfflineOfficial SDKs keep a local cache and queue writes; sync when back online (similar role to our IndexedDB cache).

3. CRDT algorithms (explore)


CRDT (Conflict-free Replicated Data Type) structures merge concurrent updates without central locks. Useful when multiple lab workstations edit offline and later sync.




Algorithm / typeBehaviourFit for this log




G-Counter / PN-Counter
Grow-only or increment/decrement counters that merge by taking per-replica max then summing.
Total CPD points across replicas; not ideal as sole store for full employee records.




G-Set / 2P-Set / OR-Set
Sets that only add (G-Set), or add+remove with tombstones (2P-Set / observed-remove set).
OR-Set suits lists of activity rows or attachment IDs when two users add different rows offline.




LWW-Register / LWW-Element-Set
Each field keeps (value, timestamp). Merge keeps the highest timestamp.
Simple per-field merge for name, outcome, dates. Clock skew can mis-order events.




MV-Register
Keeps all concurrent values until a user resolves the conflict.
Good UX for “two outcomes set offline” — surface both and let QM choose.




RGA / WOOT / Yjs-style sequences
Ordered sequences for collaborative text; complex.
Overkill for form fields; relevant only if free-text notes were co-edited live.




JSON CRDTs (Automerge, Yjs Doc)
Map CRDT operations onto nested JSON documents.
Best long-term approach for full employees[] documents if moving beyond GitHub LWW.






// Conceptual LWW field merge (not a full CRDT library)
function mergeEmployee(local, remote) {
  const out = { ...remote };
  for (const key of Object.keys(local)) {
    if (key === "id") continue;
    const lt = local._meta?.[key]?.ts || 0;
    const rt = remote._meta?.[key]?.ts || 0;
    out[key] = lt >= rt ? local[key] : remote[key];
  }
  // Activities: OR-Set style — union by activity id
  const byId = new Map();
  for (const a of [...(remote.activities||[]), ...(local.activities||[])]) {
    if (a.id) byId.set(a.id, a);
  }
  out.activities = [...byId.values()];
  return out;
}


This app today: GitHub sync is file-level optimistic LWW (SHA check), not a field-level CRDT. CRDTs would be introduced with a library (e.g. Automerge) or a backend (Firebase/Firestore) that stores operations. Practical rule remains: one editor per staff record when using GitHub Push.

async function secret(name) {
  if (cache[name] && cache[name].exp > Date.now()) return cache[name].val;

}

10. PKCE flow details (explore)


PKCE (Proof Key for Code Exchange, RFC 7636) protects the OAuth2 authorization code flow for public clients such as this browser SPA.




StepWhat happens



1. Generate verifierCreate a high-entropy random string (43–128 characters). Keep it in memory only.


2. Challengecode_challenge = BASE64URL(SHA-256(verifier)) · method S256


3. Authorize redirectSend user to IdP /authorize with client_id, redirect_uri, scope, state, code_challenge, code_challenge_method=S256


4. Login at IdPUser authenticates; IdP redirects back with code and state


5. Validate stateMust match the value you sent (CSRF protection)


6. Token requestPOST /token with grant_type=authorization_code, code, redirect_uri, client_id, code_verifier (original secret)


7. IdP verifiesHashes verifier and compares to the stored challenge — blocks intercepted codes without the verifier


8. Tokens returnedAccess token (often JWT), optional refresh token, id_token (OIDC)





// PKCE helpers (conceptual — not active login path)
function base64Url(buf) {
  const bytes = buf instanceof ArrayBuffer ? new Uint8Array(buf) : buf;
  let s = btoa(String.fromCharCode(...bytes));
  return s.replace(/\+/g,"-").replace(/\//g,"_").replace(/=+$/,"");
}
async function createPkce() {
  const raw = crypto.getRandomValues(new Uint8Array(32));
  const verifier = base64Url(raw);
  const digest = await crypto.subtle.digest("SHA-256", new TextEncoder().encode(verifier));
  return { verifier, challenge: base64Url(digest), method: "S256" };
}

  return s.replace(/\+/g,"-").replace(/\//g,"_").replace(/=+$/,"");
}
async function createPkceSession() {
  const verifier = base64Url(crypto.getRandomValues(new Uint8Array(32)));
  const state = base64Url(crypto.getRandomValues(new Uint8Array(16)));
  const nonce = base64Url(crypto.getRandomValues(new Uint8Array(16)));
  const dig = await crypto.subtle.digest("SHA-256", new TextEncoder().encode(verifier));
  const challenge = base64Url(dig);
  sessionStorage.setItem("oauth_pkce", JSON.stringify({ verifier, state, nonce }));
  return { verifier, state, nonce, challenge, method: "S256" };
}
async function exchangeCode(code, discovery, clientId, redirectUri) {
  const { verifier, state, nonce } = JSON.parse(sessionStorage.getItem("oauth_pkce") || "{}");
  sessionStorage.removeItem("oauth_pkce");
  const body = new URLSearchParams({
    grant_type: "authorization_code",
    code, redirect_uri: redirectUri, client_id: clientId, code_verifier: verifier
  });
  const res = await fetch(discovery.token_endpoint, {
    method: "POST",
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
    body
  });
  if (!res.ok) throw new Error("Token exchange failed");
  return res.json(); // { access_token, id_token, refresh_token?, expires_in }
}

// Conceptual JWKS cache with kid-miss refresh (not active)
let jwksCache = { fetchedAt: 0, keys: [] };
const JWKS_TTL_MS = 6 * 60 * 60 * 1000; // 6 hours
async function getJwks(jwksUri, force) {
  const fresh = Date.now() - jwksCache.fetchedAt < JWKS_TTL_MS;
  if (!force && jwksCache.keys.length && fresh) return jwksCache.keys;
  const res = await fetch(jwksUri);
  const doc = await res.json();
  jwksCache = { fetchedAt: Date.now(), keys: doc.keys || [] };
  return jwksCache.keys;
}
async function jwkForKid(jwksUri, kid) {
  let keys = await getJwks(jwksUri, false);
  let jwk = keys.find(k => k.kid === kid);
  if (!jwk) {
    keys = await getJwks(jwksUri, true); // rotation path
    jwk = keys.find(k => k.kid === kid);
  }
  if (!jwk) throw new Error("Unknown kid");
  return jwk;
}

# Throttle-aware refresh (Python sketch)
import time, requests

def post_with_retry(url, headers, max_tries=5):
    for attempt in range(max_tries):
        r = requests.post(url, headers=headers, json={}, timeout=60)
        if r.status_code in (200, 202):
            return r
        if r.status_code == 429:
            wait = int(r.headers.get("Retry-After", 2 ** attempt))
            time.sleep(wait)
            continue
        r.raise_for_status()
    raise RuntimeError("refresh rate-limited")

"""Power BI REST API — Python token generation (client credentials)."""
import os
import sys
import requests

TOKEN_URL = "https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token"
SCOPE = "https://analysis.windows.net/powerbi/api/.default"


def get_powerbi_token(tenant_id: str, client_id: str, client_secret: str) -> str:
    """Return a Bearer access_token for Power BI REST APIs."""
    url = TOKEN_URL.format(tenant=tenant_id)
    data = {
        "grant_type": "client_credentials",
        "client_id": client_id,
        "client_secret": client_secret,
        "scope": SCOPE,
    }
    response = requests.post(url, data=data, timeout=60)
    response.raise_for_status()
    payload = response.json()
    token = payload.get("access_token")
    if not token:
        raise RuntimeError("No access_token in response: " + str(payload))
    # expires_in is typically ~3599 seconds
    return token
